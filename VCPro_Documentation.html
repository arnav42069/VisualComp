1 Overview & Architecture

Visual Comp Pro (VCPro) is a stereo FET-modelled dynamic range compressor built as a VST3 and Standalone audio plugin using the JUCE C++ framework. It combines a musically transparent feed-forward compressor with analogue-inspired FET saturation, full real-time visual feedback, and parallel compression capability.

Design Philosophy

VCPro is modelled after the character of JFET-based hardware compressors — particularly the gain-reduction path of the Universal Audio 1176 — which use Junction Field-Effect Transistors to produce musically pleasing odd-order harmonic distortion. Unlike purely transparent "clean" compressors, VCPro intentionally colours the signal with a subtle transformer-style saturation both at the input stage and (when the Limiter is engaged) at the output stage.

All metering and visual displays are driven by lock-free ring buffers and atomic variables shared between the real-time audio thread and the GUI message thread, ensuring no audio dropouts from GUI updates.

Processing Order Detail

Every call to processBlock() follows this strict order:

  1. Guard — Check numSamples > 0, numChannels > 0; ScopedNoDenormals engaged.
  2. Read Mix — Load mix parameter once at block start to avoid per-sample APVTS reads.
  3. Copy Dry Buffer — If mix < 1.0, copy raw input into dryBuffer before any modification.
  4. Input Display Capture — Scale input by gainIn, push to inputWaveform ring buffer (mono sum).
  5. Per-Sample Loop — Input gain → FET pre-saturation → peak detection → gain computer → envelope filter → compression gain → output gain → optional limiter.
  6. Dry/Wet Blend — Mix compressed buffer with saved dry buffer.
  7. Output Display Capture — Push final mixed buffer to outputWaveform ring buffer.
  8. Atomics Update — Write gainReductionDb and currentInputLevelDb for GUI metering.

3 DSP Algorithms

3.1 FET Analog Saturation Model

VCPro models the soft-saturation behaviour of a 2N3819 N-channel JFET, the same transistor type used in the UA 1176's gain reduction path. The saturation is applied twice: at the input stage (with stronger drive proportional to Gain In) and at the output stage only when the Limiter is engaged (with a fixed gentle drive of 0.08).

The fast tanh approximation uses a degree-3/3 Padé rational approximant, accurate to within 0.001 for |x| ≤ 3:

tanh(x) ≈ x × (27 + x²) / (27 + 9x²)
Padé [3/3] approximant — error < 0.001 for |x| ≤ 3

The full FET saturation function combines an odd-order component (symmetric, produces 3rd harmonic) with an even-order asymmetric term (produces 2nd harmonic, models JFET bias-point coloration):

k = 1 + drive × 2.2
odd = tanh(x × k) / k
even = drive × 0.018 × odd × |odd|
out = odd + even
FET soft saturation — drive ∈ [0.0, 1.0]
static inline float fastTanh(float x) noexcept { const float x2 = x * x; return x * (27.0f + x2) / (27.0f + 9.0f * x2); } static inline float fetSaturate(float x, float drive) noexcept { const float k = 1.0f + drive * 2.2f; const float clipped = fastTanh(x * k) / k; // odd-order (3rd harmonic) const float asym = drive * 0.018f * clipped * std::abs(clipped); // even-order (2nd harmonic) return clipped + asym; }

Input drive scaling: fetDrive = 0.18 + gainIn × 0.003. At 0 dB Gain In the drive is a subtle 0.18; pushing Gain In to +24 dB raises drive to 0.252, increasing harmonic content naturally — just as an analogue transformer would saturate harder when driven hotter.

Why Padé instead of std::tanh? The standard library std::tanh uses a transcendental calculation that can be 5–10× slower than a rational polynomial. The Padé [3/3] approximant evaluates to effectively the same result in the audible range (error < 0.001 for inputs up to 3× full scale) at a fraction of the CPU cost, making it suitable for per-sample processing inside the hot loop.

3.2 Gain Computer (Soft Knee)

The gain computer maps the input level (in dB) to a gain-reduction amount (in dB) using a piecewise function. When a non-zero knee is set, the hard threshold edge is replaced with a quadratic curve that smoothly blends from unity gain to full compression.

Below knee:   GR = 0 dB     (no reduction)

In knee (thresh − knee/2 ≤ input ≤ thresh + knee/2):
x = input − threshold + knee/2
GR = x² × (1/ratio − 1) / (2 × knee)

Above knee:   GR = threshold + (input − threshold) / ratio − input
Feed-forward soft-knee gain computer
// Gain computer — all values in dB float grDb; if (kneeDb > 0.0f && inputDb >= (thresholdDb - halfKnee) && inputDb <= (thresholdDb + halfKnee)) { const float x = inputDb - thresholdDb + halfKnee; grDb = x * x * (1.0f / ratio - 1.0f) / (2.0f * kneeDb); } else if (inputDb > thresholdDb + halfKnee) { grDb = thresholdDb + (inputDb - thresholdDb) / ratio - inputDb; } else { grDb = 0.0f; }

The level detector uses peak detection across all channels: peakLevel = max(|L|, |R|). This is a true peak stereo compressor — both channels are reduced by the same gain amount calculated from whichever channel is loudest.

3.3 Envelope Ballistics

The gain reduction amount from the gain computer is smoothed over time by a first-order IIR (one-pole) lowpass filter. Attack and release have separate time constants, implementing the classic asymmetric ballistics of FET hardware — attack is faster (catches transients) while release is slower (avoids pumping).

attackCoeff = e^(−1 / (sampleRate × attackMs × 0.001))
releaseCoeff = e^(−1 / (sampleRate × releaseMs × 0.001))

if (GR_target < envelope):   envelope = α_atk × envelope + (1 − α_atk) × GR_target
else:                        envelope = α_rel × envelope + (1 − α_rel) × GR_target
One-pole IIR envelope follower with split attack/release
Skewed parameter ranges: Attack (0.1–200 ms) and Release (1–2000 ms) both use a skew factor of 0.3 in their NormalisableRange, meaning the knob spends proportionally more travel in the low-millisecond region where audible differences are most dramatic. Similarly, Ratio uses a skew of 0.4 to give more resolution at the musical ratios (2:1–8:1) before reaching limiting territory.

3.4 Gain Application & Hard Limiter

The smoothed envelope (in dB) is converted to a linear gain multiplier and applied to both channels, along with the Gain Out make-up gain:

compGain = dBtoLinear(envelope) × dBtoLinear(gainOut)
Combined compression + make-up gain

When the Limiter toggle is off (default), the output stage is completely transparent — no saturation or clipping is applied. When the Limiter is on, the output FET saturation (drive = 0.08) followed by a hard clip at ±1.0 (0 dBFS) is engaged:

const float out = limiterOn ? juce::jlimit(-1.0f, 1.0f, fetSaturate(compressed, 0.08f)) : compressed; // clean pass-through when limiter off

3.5 Dry/Wet Mix — Parallel Compression

The Mix knob enables parallel compression (also called New York compression): the fully processed wet signal is blended with the unprocessed dry signal captured before any gain or saturation was applied. This preserves the transient attack of the dry signal while adding the sustain and body of the compressed signal.

output = compressed × mix + rawInput × (1 − mix)
Linear crossfade — mix ∈ [0.0, 1.0]
  • Mix = 0% — Fully dry. The plugin is effectively bypassed. Output equals the unprocessed input exactly.
  • Mix = 50% — Classic New York compression. Transients punch through from the dry signal; compressed sustain adds density.
  • Mix = 100% — Fully wet. 100% of the fully processed compressed signal.
The dry signal saved for the Mix blend is the raw pre-gainIn signal. This means at Mix = 0%, the output level matches the original input regardless of Gain In or Gain Out settings, which is standard plug-in bypass behaviour.

Detailed Parameter Descriptions

THRESHOLD — Rotary knob
−60.0 to 0.0 dB, step 0.1, default −20.0 dB

Sets the level above which gain reduction begins. Signal below the threshold passes through unaffected. With a non-zero Knee, gain reduction starts gradually at Threshold − Knee/2 and reaches full ratio at Threshold + Knee/2. Lower values compress more of the programme material; higher values only catch the loudest peaks.

KNEE — Rotary knob
0.0 to 20.0 dB, step 0.1, default 6.0 dB

Width of the soft-knee transition region centred on the threshold. At 0 dB, the compressor has a hard knee — gain reduction snaps on immediately at the threshold. Larger knee values produce a gradual quadratic curve through the transition, making the onset of compression less audible and more "transparent". A 6 dB knee is typical for bus compression.

RATIO — Rotary knob
1.0 to 20.0 :1, step 0.01, skew 0.4, default 4.0 :1

The compression ratio determines how much the output increases for each dB above the threshold. At 4:1, for every 4 dB the signal exceeds the threshold, the output only rises by 1 dB. At 20:1, the compressor approaches limiting territory. The logarithmic skew (0.4) concentrates knob resolution in the 1:1–8:1 range most used musically.

ATTACK — Rotary knob
0.1 to 200.0 ms, step 0.01, skew 0.3, default 10.0 ms

How quickly the compressor responds after a signal exceeds the threshold. Implemented as the time constant of a one-pole IIR lowpass filter on the gain-reduction envelope. Shorter attack times catch transients quickly (good for limiting snare hits) but can cause pumping artefacts. Longer attack times let transients pass through before compression engages, preserving "punch".

RELEASE — Rotary knob
1.0 to 2000.0 ms, step 0.1, skew 0.3, default 100.0 ms

How quickly gain reduction recovers after the signal falls below the threshold. Implemented as a separate one-pole IIR time constant applied when the computed GR target is rising (less negative) than the current envelope. Fast release can cause audible pumping on slow material. Slow release works well for transparent bus compression.

GAIN IN Fader
−24 to +24 dB

Input gain applied before compression. Driving the input hotter increases FET saturation drive (fetDrive = 0.18 + gainIn × 0.003), adding analogue warmth. Use to push signal into the compressor or increase headroom.

GAIN OUT Fader
−24 to +24 dB

Output make-up gain applied after compression. Compensates for the gain reduction introduced by the compressor. Increase after setting threshold and ratio to restore perceived loudness.

MIX Knob
0.0 to 1.0 (0–100%)

Parallel compression blend. 0% = fully dry (bypass), 100% = fully wet (full compression). 50% blends both for classic New York compression — transients from dry + density from compressed.

LIMITER Toggle
on / off, default off

When on: applies FET output saturation (drive 0.08) then hard clips at ±1.0 (0 dBFS). When off: output stage is completely transparent — no soft clipping. Useful as a safety ceiling on master bus.

5.1 Waveform Displays

Two WaveformDisplay components sit side-by-side in the upper-left area (each approximately 333 × 198 px). They run at 120 Hz via JUCE's Timer mechanism and implement a lock-free scrolling oscilloscope backed by a 65,536-sample ring buffer.

Ring Buffer (WaveformBuffer)

Each WaveformBuffer is a plain std::array<float, 65536> with a std::atomic<int> write position. The audio thread calls push() without locking; the GUI timer reads it without locking. SPSC (single-producer, single-consumer) semantics are safe because only the audio thread writes and only the GUI timer thread reads.

Pre-computed Min/Max Display Buffer

Rather than drawing from the raw ring buffer each frame, each WaveformDisplay maintains a dispMin[] and dispMax[] pixel-width vector. Every timer tick, this buffer is shifted left by the number of new pixel columns that correspond to the new audio samples, and only the new rightmost columns are filled from the ring buffer. This makes rendering O(newColumns) not O(bufferSize), enabling stable 120 Hz updates.

INPUT
Shows pre-compression signal (after Gain In is applied). Amber colour (#dd9933). The dashed red threshold lines show the current Threshold parameter value dynamically — the waveform pointer to the threshold in APVTS is passed directly to the WaveformDisplay constructor.
OUTPUT
Shows the final post-mix signal — exactly what is written to the audio output buffer, including the Dry/Wet blend. Blue colour (#4488dd). No threshold display.

Rendering

The waveform is rendered as a filled polygon (the envelope area between min and max) with alpha 0.42, plus two anti-aliased stroke paths: a brighter top-edge trace (1.5px) and a dimmer bottom-edge trace (1.0px). Grid lines at 0, −6, −12, −20 dB are drawn as white-on-dark horizontal lines with tick marks and dB labels.

5.2 Analogue VU Meter

The VuMeter component (279 × 294 px) simulates a classic analogue VU needle movement, displaying Gain Reduction from 0 dB (needle far right) to −20 dB (needle far left).

INPUT
Data source: gainReductionDb atomic float, written by the audio thread each block.

Needle Ballistics

The needle uses a two-speed exponential smoothing filter, inspired by the mechanical inertia of a real VU movement:

α_attack = 0.42    (fast — needle snaps quickly toward higher GR)
α_release = 0.09    (slow — needle returns lazily when GR reduces)

needle += (target − needle) × α
Asymmetric ballistics running at 60 Hz

Proportional Geometry

All meter geometry — pivot point, needle length, tick radii, font size — is derived proportionally from the component's width and height at paint time. The needle length is constrained by both the width (sin 35°) and the face height (cos 35°), then the minimum is taken and scaled by 0.93 to ensure the tip never clips the face border.

5.3 Transfer Curve Display

The GrCurveDisplay (279 × 180 px, below the VU meter) shows the static input/output transfer function of the compressor and a live operating point dot. It updates at 30 Hz.

  • X-axis: Input level, −60 to 0 dBFS
  • Y-axis: Output level, −60 to 0 dBFS
  • Blue curve: The transfer function calculated from Threshold, Ratio, and Knee parameters, redrawn each frame as parameters change.
  • Red dashed line: Vertical line at current Threshold value.
  • Grey shaded region: The knee transition zone.
  • Amber dot: Live operating point — position on the curve corresponding to currentInputLevelDb (the block peak read from the atomic). The outer ring animates as a soft glow.

5.4 Controls

Rotary Knobs (SnapKnob)

Five rotary knobs control Threshold, Knee, Ratio, Attack, and Release. A sixth compact knob in the title bar controls Mix. All use a custom SnapKnob class — a plain juce::Slider subclass with no snapValue() override, ensuring logarithmically skewed parameter ranges work without the knob getting stuck at the minimum value.

Vertical Faders (Gain In / Gain Out)

6 Threading & Lock-Free Communication

Audio plugins must never block the real-time audio thread. VCPro uses three lock-free mechanisms to share data between the audio thread and the GUI message thread.

6.1 Waveform Ring Buffers (SPSC)

Two WaveformBuffer instances (inputWaveform, outputWaveform) are plain C arrays wrapped with a single std::atomic<int> write position. The audio thread is the sole writer; the GUI timer is the sole reader. No mutex or lock is needed because:

  • The array elements are aligned floats — writes are atomic on x86.
  • The writePos atomic is updated after all data is written, acting as a publication fence.
  • The reader observes stale data at worst — no corruption can occur.

6.2 Metering Atomics

Two std::atomic<float> members carry metering data from the audio thread to the GUI timer callbacks:

AtomicWritten byRead byPurpose
gainReductionDbAudio thread (per block)VuMeter timer (60 Hz)Current envelope GR value in dB, drives VU needle
currentInputLevelDbAudio thread (per block)GrCurveDisplay timer (30 Hz)Block peak input level in dB, positions operating-point dot

Both use memory_order_relaxed — correct on x86 where loads/stores are sequentially consistent for aligned values, and sufficient here since there is no dependency ordering requirement between the two atomics.

6.3 APVTS Parameter Access

The audio thread reads all parameters using apvts.getRawParameterValue("id")->load(). This returns a pointer to a std::atomic<float> maintained by JUCE's APVTS internals. Parameters are read at the start of each block (not per-sample), trading minor smoothing resolution for reduced atomic load overhead. The lone exception is the limiter boolean which is read inside the sample loop — this is acceptable because it is a boolean read with no arithmetic following it.

Why no SmoothedValue? VCPro intentionally uses one-pole IIR ballistics for attack and release rather than JUCE's SmoothedValue. The IIR filter is sample-accurate (not block-accurate), meaning gain-reduction changes are interpolated continuously rather than linearly ramped once per block. This matches the behaviour of analogue hardware more closely.

7 State Management & Preset Recall

Plugin state is managed entirely by JUCE's AudioProcessorValueTreeState. getStateInformation() copies the ValueTree to XML and serialises it to a binary MemoryBlock for the host. setStateInformation() deserialises and replaces the ValueTree, which automatically pushes parameter values to all registered APVTS Attachments and triggers GUI updates.

No custom state beyond parameters is persisted (waveform history, VU needle position, etc. are purely transient display state and are discarded on plugin reload). The APVTS state ID is "STATE".
